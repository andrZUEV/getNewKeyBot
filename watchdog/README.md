# vpnwatch — взаимный сторож

Два сервера (Прага и Москва) следят друг за другом. Если один перестаёт
отправлять пинги, второй присылает тревогу в Telegram, а когда связь
возвращается — сообщает об этом.

Пинги идут **по публичному HTTPS**, а не через туннель, поэтому проверяется
не только живой процесс, но и доступность сервера снаружи.

## Зачем это нужно

Обычный монитор внутри сервера не может сообщить о собственной смерти:
если сервер лёг, вместе с ним умолк и монитор. Здесь тревогу отправляет
**другой** сервер, который жив.

Один наблюдатель на втором сервере закрывает падение первого. Чтобы
закрыть случай «упали оба», каждый сервер дополнительно отмечается
во внешнем сервисе (`hc_ping_url`), например healthchecks.io.

## Как работает

| Что | Как часто | Примечание |
|---|---|---|
| Приём пинга от партнёра | по факту | `GET /ping/<токен>` |
| Пинг партнёра | `ping_every` (120 с) | по публичному HTTPS |
| Пинг внешнего сервиса | `ping_every` | если задан `hc_ping_url` |
| Проверка тишины | 15 с | порог `alert_after` (600 с) |

Тревога отправляется **один раз** на инцидент, затем отдельное сообщение
о восстановлении. Спама не будет.

`GET /status` отдаёт страницу состояния: когда был последний пинг и
доступен ли партнёр. Удобно проверять с телефона.

## Установка

```bash
mkdir -p /opt/vpnwatch
cp watch.py /opt/vpnwatch/
cp vpnwatch.service /etc/systemd/system/
# создать /opt/vpnwatch/config.json (см. ниже)
systemctl daemon-reload
systemctl enable --now vpnwatch
```

## Конфигурация

Файл `/opt/vpnwatch/config.json`, права `600`:

```json
{
  "role": "prague",
  "listen_port": 9443,
  "cert": "/usr/local/etc/xray/cert/fullchain.pem",
  "key": "/usr/local/etc/xray/cert/privkey.pem",
  "token_in": "<токен, который присылает партнёр>",
  "partner_name": "Москва",
  "partner_ping": "https://45-154-185-199.sslip.io:8443/ping/<токен>",
  "ping_every": 120,
  "alert_after": 600,
  "hc_ping_url": ""
}
```

| Поле | Смысл |
|---|---|
| `role` | имя сервера в сообщениях |
| `listen_port` | на каком порту слушать (Прага 9443, Москва 8443) |
| `cert` / `key` | сертификат и ключ для HTTPS |
| `token_in` | токен, который должен прислать партнёр |
| `partner_name` | как называть партнёра в тревогах |
| `partner_ping` | полный URL партнёра вместе с ЕГО токеном |
| `ping_every` | период пингов, секунды |
| `alert_after` | через сколько секунд тишины тревога |
| `hc_ping_url` | необязательный внешний наблюдатель |

**Важно:** два токена, они не должны совпадать.

- `token_in` на Праге — это токен, который присылает Москва; он же стоит
  в `partner_ping` у Москвы.
- `token_in` на Москве — токен, который присылает Прага; он же стоит
  в `partner_ping` у Праги.

## Уведомления

Сторож вызывает `/usr/local/bin/tg-notify.sh "<текст>"`. Скрипт берёт
`TG_TOKEN` и `TG_CHATS` из `/etc/tg-notify.env`. Отдельного конфига
с секретами vpnwatch не требует.

## Диагностика

```bash
systemctl status vpnwatch
journalctl -u vpnwatch -n 30 --no-pager
curl -s https://<свой-адрес>:<порт>/status
curl -s https://<партнёр>:<порт>/ping/<токен>   # проверка вручную
```

Проверка тревоги без ожидания 10 минут — временно уменьшить порог:

```bash
# в config.json поставить "alert_after": 30, затем
systemctl restart vpnwatch
# остановить партнёра и подождать ~45 с
```
