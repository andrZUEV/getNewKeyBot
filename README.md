# getNewKeyBot

Telegram-бот для выдачи и отзыва ключей **VLESS + WebSocket + TLS** (Xray).
Только стандартная библиотека Python — зависимостей нет.

## Схема

```
Клиент ──> Сервер 1:443 (проброс TCP) ──> Сервер 2:443 (TLS) ──> интернет
       ──> Сервер 2:443 напрямую
       ──> Сервер 2:443 (второй IP, необязательно)
```

Точек входа — от одной до трёх, ключ на каждую. Выход всегда через Сервер 2.

**Незаданный адрес не выдаётся.** Если `DOMAIN_SERVER2_ALT` (или любой другой)
пуст, бот просто не включает его в ключи — вместо того чтобы собрать нерабочую
ссылку вида `vless://uuid@:443?...`. Так можно безопасно вывести вышедшую из
строя точку входа из эксплуатации, не меняя код.

Сервер 1 работает как прозрачный проброс TCP: TLS завершается на Сервере 2, поэтому
Сервер 1 видит только шифрованный поток и расшифровать его не может. Сертификат
на домен Сервера 1 лежит на Сервере 2 — отсюда сквозное шифрование.

## Возможности

- **Добавить клиента** — спрашивает имя, генерирует UUID, выдаёт ключ
- **Добавить несколько** — префикс и количество за один раз: `телефон 5`.
  Каждому подключению добавляется случайный хвост (`телефон-a3k9`,
  `телефон-p7mq`), чтобы имена не совпадали и устройства не путались.
  Ключи приходят в ответ отдельными сообщениями, **разделённые пустой строкой**;
  при большом количестве пачка автоматически режется по лимиту Telegram (4096 символов)
- **Подписка** — в карточке клиента одна ссылка-подписка для Hiddify, v2rayNG,
  NekoBox и подобных клиентов: они сами обновляют список серверов
- **Подписки (несколько)** — префикс и количество, как при добавлении: создаются
  клиенты и выдаются их ссылки-подписки, по одной на устройство
- **Список клиентов** — кнопки с именами
- **Карточка клиента** — новые ключи, переименование, удаление (с подтверждением)
- **Другие адреса** — ссылки на остальные точки входа
- Ключи сохраняются текстовыми файлами: `data/keys/<имя>.txt`
- Доступ только для указанных Telegram ID
- Работает через long polling: входящие порты не нужны, боту всё равно, заблокирован ли IP

## Установка

```bash
git clone git@github.com:andrZUEV/getNewKeyBot.git /tmp/vpnbot
cd /tmp/vpnbot
bash install.sh
nano /opt/vpnbot/.env
systemctl restart vpnbot
journalctl -u vpnbot -f
```

## Конфигурация

Всё в файле `.env` рядом с `bot.py`. Шаблон — `.env.example`.

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) |
| `ADMIN_IDS` | Telegram ID через запятую. Пусто = доступ всем (не для прода) |
| `XRAY_CONFIG` | путь к конфигу Xray, по умолчанию `/usr/local/etc/xray/config.json` |
| `XRAY_SERVICE` | имя systemd-юнита Xray, по умолчанию `xray` |
| `KEYS_DIR` | каталог для файлов с ключами, относительно каталога бота |
| `DOMAIN_SERVER1` | адрес входа через Сервер 1 |
| `DOMAIN_SERVER2` | основной адрес выхода (Сервер 2) |
| `DOMAIN_SERVER2_ALT` | второй адрес Сервера 2 (необязателен: пусто = не выдаётся) |
| `SUB_BASE` | публичный адрес сервиса подписок, например `https://195-110-217-179.sslip.io:2096` |
| `SUBS_DB` | путь к базе токенов подписок, по умолчанию `/opt/vpnsub/subs.json` |

Свой Telegram ID можно узнать у [@userinfobot](https://t.me/userinfobot) или командой `/id` в боте.

## Подписки

Вместо набора ключей клиенту можно выдать **одну ссылку-подписку**. Клиент
(Hiddify, v2rayNG, NekoBox, sing-box) периодически забирает её сам и обновляет
список серверов — новые адреса и протоколы появляются без пересылки ключей.

```
https://195-110-217-179.sslip.io:2096/sub/<токен>
```

Серверная часть — отдельный маленький сервис в каталоге `vpnsub/`
(только стандартная библиотека Python):

- слушает `2096/tcp` по HTTPS с тем же сертификатом, что и Xray;
- список клиентов берёт из конфига Xray, адреса — из `.env` этого бота
  (`DOMAIN_SERVER1/2/2_ALT`), поэтому подписка всегда совпадает с выдачей ключей;
- отвечает base64-списком ссылок `vless://` плюс заголовки `Profile-Title`
  и `subscription-userinfo` (учёта трафика в Xray нет, поэтому нули);
- **токен и есть доступ**: 24 случайных байта. На чужой токен отвечает `404`,
  причём так же, как на любой несуществующий путь — существование клиента
  по ответу не определить.

Токены лежат в `/opt/vpnsub/subs.json` (права `600`). Выдаются при первом
запросе подписки, сохраняются при переименовании клиента и **отзываются
при удалении**. Повторный запрос возвращает тот же токен, а не новый.

Установка сервиса (рядом с ботом, на том же сервере, где Xray):

```bash
mkdir -p /opt/vpnsub
cp vpnsub/sub.py /opt/vpnsub/sub.py
echo '{}' > /opt/vpnsub/subs.json && chmod 600 /opt/vpnsub/subs.json
cp vpnsub/vpnsub.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now vpnsub
ufw allow 2096/tcp
```

В `.env` бота добавить `SUB_BASE` (см. таблицу выше) и перезапустить бота.

## Требования

- Python 3.8+ (стандартная библиотека)
- `xray` в PATH, конфиг VLESS+WS+TLS, клиенты в `inbounds[0].settings.clients`
- systemd, права root (бот перезапускает службу `xray`)

## Файлы

```
bot.py             — бот
.env.example       — шаблон конфигурации (публикуется)
.env               — реальные секреты (в .gitignore)
vpnbot.service     — systemd-юнит
install.sh         — установка
vpnsub/sub.py      — сервис подписок (HTTPS, порт 2096)
vpnsub/vpnsub.service — systemd-юнит сервиса подписок
data/keys/         — текстовые файлы с ключами (в .gitignore)
```

## Безопасность

- `.env` не попадает в git (`.gitignore`)
- Бот не открывает портов — только исходящие запросы к Telegram
- Список `ADMIN_IDS` обязателен в проде
- Запросы к Telegram идут по IPv4: IPv6-маршрут периодически зависает в `SYN-SENT`
